# WebP lossless recompression — deliverables

## What changed

Leanify previously only moved WebP files through as generic data. The change
adds one optional format module plus a few small wiring edits, reusing the
same identification and write-back entry as PNG and AVIF:

- `formats/webp.h`, `formats/webp.cpp` — new `Webp` handler (RIFF/VP8X
  container + chunk parser, libwebp lossless re-encode).
- `leanify.cpp` — one detection branch in the existing magic-based `GetType`
  chain, next to the PNG and AVIF branches; no separate pipeline.
- `Makefile` — optional, pkg-config-auto-detected libwebp linkage
  (`WEBP=0` or a missing pkg-config entry builds the original feature set).
- `formats/avif.h`, `formats/avif.cpp` — the AVIF handler this entry is
  shared with (same `GetType` chain, same in-place write-back contract).
- `README.md`, `CHANGELOG.md` — documentation.

No PNG/JPEG code path was modified.

## How the lossless guarantee works

1. Recognize the container by its `RIFF....WEBP` magic and validate the RIFF
   size field against the actual file length.
2. Walk every RIFF chunk with explicit bounds checks (fourcc, little-endian
   size, odd-byte padding), remembering `VP8X`, `ICCP`, `EXIF`, `XMP` and
   rejecting animated (`ANIM`/`ANMF`) files.
3. Decode the still image to RGBA with libwebp. Lossy `VP8 ` bitstreams are
   skipped with a diagnostic because they cannot be re-encoded losslessly
   without growing.
4. Re-encode the pixels with the libwebp lossless encoder
   (`WebPConfigLosslessPreset`, `exact=1` so RGB under fully transparent
   pixels is preserved), extract the new `VP8L` chunk and rebuild the
   container, carrying `VP8X` flags and metadata chunks over.
5. Decode the rebuilt file again and compare every RGBA sample byte for
   byte; any mismatch aborts and the original file is kept.
6. The new payload is only written when it is strictly smaller. All work
   happens in separate memory buffers; the mapped file is touched once, with
   a single contiguous `memmove`, so a failure can never leave a torn file.

Bad/unsupported files print a diagnostic and remain byte-identical:

- truncated container or chunk header,
- RIFF size field that overruns the file,
- chunk payload that overruns the file,
- missing image bitstream, invalid dimensions, decode/encode failure,
- animated WebP and lossy (VP8) WebP,
- `-f` fast mode skips recompression.

Trailing bytes after the declared RIFF payload are treated as junk and
dropped together with the verified, smaller recompression.

## Build

The repository entry point is the Makefile. libwebp is optional and picked up
through pkg-config; when absent the handler compiles to an explicit
"not compiled in" skip:

```sh
# with WebP support (this environment uses a static libwebp prefix)
export PKG_CONFIG_PATH=/tmp/libwebp-static/lib/pkgconfig:/tmp/pkgcfg
make

# original build, zero WebP/AVIF dependencies
make WEBP=0 AVIF=0
```

Both builds are clean under the repo's `-Wall -Werror -Wextra` flags, and an
AddressSanitizer build (`make asan`) reports no errors or leaks over the
whole fixture set. The enabled binary links libwebp/libsharpyuv (and
libavif/libaom) statically here, so its runtime `NEEDED` entries match the
baseline binary.

## Verification

`run_acceptance.sh` drives the built `leanify` binary over every fixture and
checks the four acceptance criteria. Latest run: **35 passed, 0 failed**
(see `acceptance_report.txt`; working artifacts under `acceptance/`).

- Lossless identity: ffmpeg decode of before/after to raw RGBA, `cmp` per
  fixture, including the alpha-bearing image.
- Size never increases: asserted for every fixture; already-optimal and
  lossy sources are kept verbatim.
- Failure never corrupts: truncated, bad-RIFF-size, animated and lossy
  inputs remain byte-identical (md5 comparison) with diagnostic messages.
- Entry reuse / no regression: the same `GetType` entry handles PNG, WebP
  and AVIF; PNG/JPEG output is byte-identical to the `WEBP=0 AVIF=0`
  baseline binary, and magic-based detection works without a `.webp`
  extension.

Fixtures in `fixtures/` are generated by `make_fixtures.py` (Pillow +
libwebp) and cover lossless simple/VP8X stills, alpha, metadata (XMP/EXIF),
lossy, animated, truncated, bad RIFF size, trailing junk, plus PNG/JPEG.
